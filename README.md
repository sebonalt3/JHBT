# 지후배틀

소스 진입점은 `jihoo-v3.2/index.html`입니다. ZIP을 풀면 `index.html`이 압축 해제 폴더의 루트에 있습니다. `index.html`, `character-balance.js`, `firebase-config.js`, `firebase-online.js`, `portraits/`를 같은 웹 루트에 올리면 별도 빌드 없이 정적 웹 서버나 GitHub Pages에서 실행됩니다. 게임 기록은 브라우저에 저장되고 Firebase 계정을 연결한 경우 Firestore에도 백업됩니다.

저장소 루트에서 산출물을 다시 만들 때는 `python3 jihoo-v3.2/build-release.py /path/to/output`을 실행합니다. ZIP을 풀어 그 폴더에서 작업한다면 `python3 build-release.py /path/to/output`을 실행합니다. 별도 `index.html`은 로컬 JS와 초상화를 포함해 파일 하나로 실행됩니다. GitHub Pages를 사용한다면 저장소의 **Settings → Pages**에서 현재 배포 소스와 경로를 확인하고 해당 위치에 ZIP의 내용을 올리세요.

## 릴리스 관리

현재 버전은 **3.2**입니다. 릴리스마다 담당자가 `index.html`의 문서 제목, 로비 버전 배지·요약, `PATCH_NOTES`의 최신 항목을 함께 업데이트합니다. 자동으로 버전 이름이나 패치노트를 생성하지 않습니다. 캐릭터 수치는 `character-balance.js`, 희귀도와 뽑기 가중치 및 특수 전투 동작은 `index.html`, 초상화는 `portraits/`에서 관리합니다.

v3.1은 신규 지후 6기와 히든 등급(뽑기 0.3%, 덱당 1기)을 추가했습니다. 투기장은 일반 로비에서 제거하고 설정의 개발자 모드에서만 열 수 있습니다. 개발자 모드는 SHA-256으로 비밀번호를 확인하며 새로고침 시 꺼집니다. 게임은 정적 클라이언트이므로 개발자 모드 인증은 서버 보안 경계가 아닙니다. 상대 진영은 항상 보이며 플레이어의 배치·업그레이드·스킵 직후 상대도 행동합니다. 일반 전투와 투기장은 100초 시간 종료 시 화면에 표시된 승률로 승패를 정하고 50:50이면 같은 라운드를 처음부터 다시 진행합니다. 성뿌수기는 기존 30초 규칙을 유지합니다. 리더보드에는 레벨과 최근 덱 초상화를 표시하며 체력바와 빠따·오락기·인공위성·지뢰·빔·힐 지후의 밸런스를 조정했습니다. 변신 중인 미믹 지후에는 점멸하는 무지개 테두리를 표시합니다.

행성 지후 주위를 도는 **위성 지후**는 기존 **인공위성 지후**와 별개의 소환 효과입니다. 위성 지후는 전용 `portraits/planet_satellite.png`를 쓰고 미니 지후와 같은 48px 크기로 표시됩니다. 인공위성 지후는 기존 `portraits/satellite.png`를 그대로 씁니다.

## AI 에이전트 릴레이 작업 지침

이 게임은 여러 AI 에이전트가 각자의 한도에 도달하면 다음 에이전트에게 이어서 맡기는 방식으로 관리합니다. 먼저 현재 작업 요청과 직전 인계 내역, 변경 파일을 읽고 끝난 작업과 남은 작업을 구분하세요. 이미 확인된 항목은 변경된 입력이 없으면 다시 실행하지 말고, 새 변경과 그 영향을 검증하세요.

- `index.html`은 화면, 게임 흐름, 전투 엔진, 캐릭터 설명, 뽑기 확률과 `PATCH_NOTES`를 포함합니다. `character-balance.js`에는 기본 수치와 스킬 상수가 있습니다. 동작과 문구가 어긋나지 않도록 양쪽을 함께 확인하세요.
- `portraits/`의 파일 경로는 `index.html`의 `PORTRAITS`에 등록합니다. 새 지후를 만들면 게임 화면, 캐릭터 선택, 덱, 뽑기, 봇과 패치노트에서 공개 범위를 점검하세요. 해금 전 히든의 초상화와 능력은 선택창에 노출하지 않습니다.
- 전투 변경은 실제 브라우저에서 배치부터 라운드 종료까지 확인하세요. 짧은 임시 테스트 파일을 썼다면 배포 파일에서 제거하세요. 인라인 자바스크립트와 `character-balance.js` 문법도 확인하세요.
- 배포용 ZIP은 이 폴더의 내용을 루트에 담고, 별도 업로드용 `index.html`에는 로컬 JS와 초상화 파일을 포함해야 단일 파일로 동작합니다. 새 수정 뒤 위 명령으로 두 파일을 다시 만들고 검사하세요.

v3.0.3에서는 탄핵 지후의 ATK, 탄핵 지속시간, 발동 피격 횟수, 쉴드량을 조정하고 NO U의 반사 지속시간과 돌격 지후의 돌격 속도를 높였습니다. 전황 예측은 적군을 왼쪽, 아군을 오른쪽에 표시하며 쉴드 게이지는 하늘색, 쿨타임 게이지는 주황색으로 표시합니다. 상세 수치는 게임 안의 패치노트를 참조하세요.

v3.0.2부터 덱 슬롯은 3개입니다. 이전 4·5번 슬롯의 덱은 지후 선택창의 **이전 덱 보관**에서 불러온 뒤 현재 슬롯에 저장할 수 있습니다. 불러오기만으로 기존 1~3번 덱을 덮어쓰지 않습니다.

v3.0.2 패치노트는 변경된 지후 18기를 각각 상향 8기, 하향 8기, 조정 2기로 분류하고 이전·이후 수치를 표시합니다. 메뉴, 선택창, 상점, 뽑기, 설정, 전투 HUD와 정산 화면은 블랙&화이트 2D 테마로 개편했습니다. 환경설정에서 라이트·다크 모드를 바꾸면 전체 화면에 즉시 적용되며 선택은 프로필에 저장됩니다. 상시 파티클과 무거운 블러·그림자 효과를 제거하고 결과·정산처럼 필요한 순간에만 짧은 애니메이션을 사용합니다. 마지막 유닛이 사망하면 카메라가 사망 위치를 클로즈업하고 2초간 느린 사망 연출을 보여준 뒤 라이프를 차감합니다. 보상은 정산 화면에서 한 항목씩 표시됩니다. 상단의 전황 예측은 현재 생존 병력의 체력·방어막·예상 화력과 최근 3초의 실제 피해를 함께 사용한 **추정치**이며, 통계적으로 보정된 실제 승률은 아닙니다.

v2.3.5에는 신규 지후 9기(사신·연막·충전·탄핵·폭탄·드래곤·메테오·블리자드·빔), 등급·밸런스와 뽑기 가중치 조정, 초상화 별도 파일 배포가 포함됩니다. 전체 내역은 게임 안의 **패치노트**에서 확인할 수 있습니다.

## Firebase 온라인 기능 활성화

`firebase-config.js`에 `jihoobattle` 프로젝트의 웹 앱 설정이 들어 있습니다. 이 파일은 `index.html`의 `<body>` 마지막에서 `firebase-online.js`보다 먼저 읽히고, `firebase-online.js`가 Firebase SDK를 불러와 앱을 초기화합니다. Firebase 콘솔 예시의 `<script type="module">`를 추가로 붙이면 중복 초기화가 일어나므로 붙여넣지 마세요. **실제 온라인 기능을 쓰려면 콘솔에서 인증 방식과 Firestore를 별도로 활성화해야 합니다.** 관리용 서비스 계정이나 복구 키는 파일에 저장하지 마세요.

1. `jihoobattle` 프로젝트의 Firebase Authentication에서 **이메일/비밀번호** 로그인 방식을 활성화하고 Cloud Firestore 데이터베이스를 생성합니다. 웹 API 키는 공개 클라이언트 설정이지 백업용 비밀 키가 아닙니다.
2. Firebase 콘솔의 Firestore Database → 규칙에서 **이 저장소의 `firestore.rules` 전체**를 게시합니다. 예전에 사용한 다른 게임의 규칙을 붙여넣지 마세요. CLI를 쓴다면 해당 프로젝트로 `firebase deploy --only firestore:rules --project <프로젝트-ID>`를 실행할 수 있습니다. 배포 전에는 온라인 기록 쓰기가 거부될 수 있습니다.
3. 페이지를 다시 열어 닉네임과 **비밀번호(6~32자)**를 입력하면 온라인 계정이 만들어지고, **8자리 UID**가 자동으로 배정되어 한 번 표시됩니다. UID는 안전하게 보관하고 비밀번호는 기억해 두세요. 기존에 닉네임만 만든 사람은 프로필 → 온라인 계정 만들기에서 비밀번호를 정해 등록합니다. 백업은 게임 기록 변경 후 자동으로 시도되며 프로필의 **지금 백업**으로 재시도할 수 있습니다.
4. 다른 브라우저에서 이어할 때는 첫 화면(또는 프로필)의 **UID와 비밀번호로 로그인**을 이용합니다. UID만으로는 로그인할 수 없습니다. 프로필의 **비밀번호 변경**에서 현재 비밀번호를 확인한 뒤 새 비밀번호로 바꿀 수 있습니다. Firebase Authentication의 내부 사용자 ID는 8자리 UID와 다르며, 내부 ID를 리더보드 문서 키로 사용합니다. 백업은 로그인한 본인만 읽고 쓸 수 있습니다.

v3.0.1부터 UID는 8자리(10000000~99999999)이며 계정을 만들 때 무작위로 배정됩니다(사용 중인 번호는 자동으로 건너뜁니다). 이전 버전(3.0)에서 만든 **4자리 UID 계정**은 그대로 로그인할 수 있고, 이때 비밀번호 칸에는 당시 발급된 32자 복구 키를 입력합니다. 이후 프로필에서 비밀번호를 바꿔 두세요. 비밀번호는 Firebase Authentication이 관리하며 게임 파일이나 백업 문서에는 저장되지 않습니다. 비밀번호를 잊어버리면 현재 이메일 재설정 수단이 없어 복구할 수 없으니 UID와 함께 보관하세요. 공개 리더보드에는 UID·비밀번호·백업 내용이 포함되지 않습니다. **리더보드 수치는 클라이언트가 업로드하므로 조작 방지까지 보장하지는 않습니다.** 이를 보장하려면 서버에서 전투 결과를 검증하는 별도 기능이 필요합니다.


v3.2는 인벤토리, 첫 정상 완료 후 7일 출석부, 단계별 업적, 10분 경험치 ×2 부스트를 추가했습니다. 항복은 패배로 기록하고 출석부 해금에는 포함하지 않습니다. 맵과 최대 유닛 수를 줄였으며 폭군·NO U 수치를 조정했습니다.
